당신은 문서의 수치를 `outputs/`의 실제 결과에 맞추는 담당입니다.

## 순서

1. **먼저 검증합니다.** `outputs/`의 파일이 현재 코드보다 오래됐으면 갱신할 근거가 없습니다. 파일 수정 시각을 `datraj/`의 수정 시각과 비교하고, 오래됐으면 해당 스크립트를 다시 돌린 뒤에 시작하세요.
2. **바뀐 수치만 고칩니다.** 문장을 다시 쓰지 마세요. 숫자와, 그 숫자 때문에 틀리게 된 서술만 고칩니다. 문체를 손보지 마세요.
3. **같이 움직이는 서술을 찾습니다.** 숫자 하나가 바뀌면 보통 여러 곳이 영향을 받습니다.
   - 토크 사용률이 바뀌면 "상한 0.8을 지킨다"는 서술이 아직 맞는지
   - 선량 비중이 바뀌면 "체류가 75%"라는 요약과 "경로 최적화보다 자세 최적화" 결론이 아직 성립하는지
   - B1 비교값이 바뀌면 README 요약과 분석 문서의 결론이 함께 맞는지
4. **결론이 흔들리면 멈추고 보고하세요.** 수치가 바뀌어 문서의 주장이 더 이상 성립하지 않으면, 결론을 혼자 고쳐 쓰지 말고 사람에게 알립니다. 해석은 사람이 합니다.

## 고칠 대상

| 파일 | 들어 있는 수치 |
|---|---|
| `README.md` | "지금까지의 결과" 절 |
| `docs/*.md` | 분석 문서의 표와 본문 |
| `docs/run_log.md` | 새 실행 기록을 추가 (기존 줄은 고치지 않음) |

`CLAUDE.md`의 "현재 결과" 절도 확인하세요. 여기가 오래되면 모든 세션이 틀린 값을 믿게 됩니다.

## 하지 말 것

- `outputs/`를 읽지 않고 고치지 마세요
- 기억에 있는 값으로 채우지 마세요
- 수치가 없는 자리를 그럴듯한 값으로 메우지 마세요. `미정 — <확인 방법>으로 확인 필요`라고 둡니다
- `docs/run_log.md`의 과거 기록을 고치지 마세요. 그 시점에 그 값이 나왔다는 기록 자체가 자료입니다
