# 프로젝트 안내 (Claude Code용)

이 파일은 이 저장소에서 작업하는 Claude Code 세션이 먼저 읽는 규칙입니다.

## 무엇을 하는 프로젝트인가

OECD NEA EM-POWER HER 엔지니어링 분과 **E 파트**. 선박형 용융염로(MSR)의 오프가스 흡착 베드를 원격 교체할 때, 매니퓰레이터의 **부품별 누적선량**을 계산하고 선량·시간·동역학 부하를 함께 보는 궤적 최적화기를 PyBullet으로 만듭니다.

핵심 주장은 하나입니다. **기존 연구처럼 로봇을 점(TCP) 하나로 보면 부품 선량을 대표하지 못한다.** 그래서 부품 10개(C01~C10)를 따로 평가합니다.

담당: 백재은. 다른 파트(방사선·소재·제어·공정)와 파일로 값을 주고받습니다.

## 작업 태도

Andrej Karpathy의 관찰에서 나온 네 가지 규칙을 이 프로젝트에 맞게 적용합니다. 출처는 [multica-ai/andrej-karpathy-skills](https://github.com/multica-ai/andrej-karpathy-skills)입니다.

1. **생각을 먼저 하세요 (Think Before Coding).** 가정하지 말고, 헷갈리는 것을 숨기지 말고, 선택지를 드러내세요. 요청이 두 가지로 읽히면 둘 다 제시하고 물어봅니다. 이 프로젝트에서는 특히 **물리적 가정**(질량, 속도, 체류 시간, 좌표계, 단위)을 암묵적으로 정하지 마세요.
2. **단순한 것부터 (Simplicity First).** 문제를 푸는 최소한의 코드만. 요청하지 않은 기능, 지금 쓰지 않는 추상화, 나중을 위한 일반화를 넣지 마세요. 이 저장소는 연구 코드이고 읽는 사람은 로봇공학 전공자가 아닙니다.
3. **수술하듯 고치세요 (Surgical Changes).** 고쳐야 할 것만 건드립니다. 기존 코드 스타일을 유지하고, 내 변경 때문에 쓸모없어진 코드만 지웁니다. 원래 있던 죽은 코드는 그대로 둡니다.
4. **성공 기준을 정하고 확인될 때까지 (Goal-Driven Execution).** "되게 해줘"를 검증 가능한 목표로 바꾸세요. 이 프로젝트의 검증은 대부분 **스크립트를 실제로 돌려서 숫자를 보는 것**입니다. 돌려보지 않고 "고쳤습니다"라고 하지 마세요.

## 반드시 지킬 것

1. **수치를 추측하지 마세요.** 선량, 시간, 토크 값을 말하거나 문서에 쓸 때는 `outputs/`의 CSV·JSON을 읽거나 해당 스크립트를 직접 실행해서 확인한 값만 씁니다. 기억이나 문서에 적힌 값을 그대로 옮기지 말고, 출처 파일을 확인하세요.

   모르는 값은 그럴듯하게 지어내지 말고 이렇게 적습니다.
   ```
   미정 — <확인 방법>으로 확인 필요
   가정 — <근거>. <방법>으로 검증 필요
   ```
   예: `TID_max: 미정 — 소재 파트 회신 필요`, `체류 60 s: 가정 — 공정 파트 확인 필요`. 비슷한 선례가 없으면 "선례 없음"이라고 쓰고, 있는 척 만들어내지 마세요.
2. **지금 선량 절대값은 의미가 없습니다.** 가상 선원(`config/virtual_sources.json`)으로 돌린 값입니다. 부품 사이, 단계 사이, 알고리즘 사이의 **상대 비교**로만 서술하세요. "C09가 541.9 mGy를 받는다"가 아니라 "가상 선원 기준으로 C09가 가장 크고 C10의 4.6배"처럼 씁니다.
3. **한국어로 답하세요.** 문서도 한국어로 씁니다. 전문용어는 한국어를 쓰되 처음 나올 때 괄호로 원어를 적습니다.
4. **앤대시(–)와 em dash(—)를 쓰지 마세요.** 쉼표, 괄호, 문장 분리로 처리합니다.
5. **단위를 반드시 붙이세요.** 길이 m, 각도 rad(표에서는 deg 병기 가능), 질량 kg, 토크 N·m, 선량 Gy 또는 mGy, 선량률 Gy/h. 코드 안의 각도는 전부 rad입니다.
6. **`main` 브랜치에서 작업하지 마세요.** 팀 규칙입니다. 작업 브랜치는 `Jaeeun-B`입니다. PR과 merge는 팀 논의 후에만 합니다.
7. **`git push`를 대신 하지 마세요.** 커밋까지만 하고, push는 사용자가 직접 합니다.
8. **커밋 작성자를 바꾸지 마세요.** 이 저장소의 커밋은 사용자 본인 이름으로 남아야 합니다.

## 실행 방법

```bash
conda activate eph          # Python 3.11, pybullet(conda-forge), toppra(소스 빌드)
python scripts/00_check_env.py
```

스크립트는 번호 순서대로 실행합니다. 의존 관계는 아래와 같습니다.

| 스크립트 | 전제 | 내용 |
|---|---|---|
| `00_check_env.py` | | 패키지 점검 |
| `01_make_virtual_grids.py` | | 가상 선량 격자 생성 (N = 25, 50, 100) |
| `check_dose_grid.py <npy경로>` | 01 | 격자 형식 점검. **인자 필수** |
| `02_build_scene.py [--gui]` | | 배치도 → PyBullet 장면 |
| `03_validate_line.py` | | 시간 적분·격자 보간 오차 검증 |
| `04_validate_arc.py` | | 참고문헌 3 조건 재현 |
| `05_solve_waypoints.py` | | S1~S6 웨이포인트 IK (19개 구간) |
| `06_run_b0.py [--gui]` | | B0: RRT-Connect + 경로 단축 + TOPP-RA |
| `07_run_b1.py` | **06 먼저** | B1: TCP 3D A* + IK 추종. B0 결과가 있어야 비교표 생성 |
| `08_payload_check.py` | | 베드 질량별 경사 포락선 토크 점검 |
| `10_export_handoff.py` | 06 | `handoff/` 인계 파일 생성 |

`06`, `07`에 `--field grid --N 100`을 주면 격자 경로, 기본값 `--field model`은 해석식 경로입니다.

## 현재 결과 (2026-10-02 기준, 가상 선원)

문서에 인용하기 전에 `outputs/b0/summary_b0.json` 등으로 확인하세요. 값이 바뀌었으면 문서를 고쳐야 한다는 신호입니다.

- B0: 총 189.9 s(동작 59.9 s), 토크 사용률 0.776(상한 0.8), 계획 구간 최소 여유거리 0.031 m
- 부품 선량 합의 구성: 체류 75%, 베드 근처 직선 22%, 경로계획 구간 3%. S2 커플링 해제 60 s 하나가 59%
- 최대 선량 부품은 C09 손목 카메라. 점 로봇(TCP) 값은 C09의 1.7배(과대), 원호 기준 조건에서는 A4의 1/4.9(과소)
- B1은 계획 구간 선량을 21% 줄이지만 이동 구간 전체로는 2.1%, 작업 전체로는 0.6%
- 허용 최대 베드 질량 17.1 kg (A6 손목 토크, 경사 22.5°)

**이 결과의 함의:** 경로 선택(P1, P2)보다 체류 자세 최적화(P3)와 근접 구간 속도가 선량을 좌우합니다. 단 체류 60 s와 근접 5 cm/s는 가정값이라 공정 파트 값이 오면 다시 봐야 합니다.

## 폴더 구조

```
config/      설정. 값을 바꿀 때는 여기만 고치고 params_version을 올린다
datraj/      코드 본체
scripts/     실행 스크립트 (번호 순서)
handoff/     다른 파트에 넘기는 양식과 파일. 10_export_handoff.py가 생성
docs/        분석 문서와 그림
refs/        참고문헌 PDF와 정리 노트. PDF 자체는 커밋하지 않음
data/        선량 격자 (생성물, git 제외)
outputs/     결과 (생성물, git 제외)
```

## 커밋하지 않는 것

`.gitignore`에 들어 있지만 사람이 실수하기 쉬운 것들입니다.

- `outputs/` 전체와 `data/dose_grids/*.npy`: 스크립트로 다시 만들 수 있습니다
- `refs/*.pdf`: 저작권이 있는 논문입니다. 공개 저장소에 올리지 않습니다. 정리 노트(`refs/notes/*.md`)만 커밋합니다
- `.claude/settings.local.json`: 개인 설정

`10_export_handoff.py`를 다시 돌리면 `handoff/01_radiation/sample/*_meta.json`의 `created_at`과 xlsx가 바뀐 것으로 표시됩니다. 내용 변화가 없으면 커밋하지 마세요.

## 알아둘 함정

- **toppra가 없으면** 코드는 5차 다항식 대체 방식으로 끝까지 돌지만, B0 토크 사용률이 0.97로 상한 0.8을 넘습니다. `06_run_b0.py` 로그에 계획 구간이 `[toppra]`로 찍히는지 확인하세요. `[quintic]`이면 결과를 신뢰할 수 없습니다.
- **RRT 시드가 하나입니다.** B0 궤적은 시드에 따라 달라집니다. 특히 S4 "Bed A 자리로 운반" 구간에 z = 1.35 m까지 올라가는 우회가 있습니다. B0와 B1의 동작시간·토크 차이를 해석할 때 이 점을 밝혀야 합니다.
- **`05_solve_waypoints.py`의 "노즐 결합" 여유거리가 -0.000입니다.** 결합 동작이라 접촉이 의도된 값이고 오류가 아닙니다.
- **PyBullet GUI 창을 닫으면** 재생이 정상 종료됩니다(2026-10-02 수정). 에러가 다시 나면 `datraj/viz.py`의 예외 처리를 확인하세요.
- **그림의 한글 글꼴**은 `datraj/viz_style.py`가 OS별로 찾습니다. 네모로 보이면 글꼴 목록에 추가하세요.

|---|---|---|

## 문서의 역할 분담

각 사실은 **주인이 되는 문서 하나**에만 적습니다. 같은 수치를 여러 문서에 복사하면 반드시 어긋납니다.

| 역할 | 파일 | 담는 것 |
|---|---|---|
| 규칙 | `CLAUDE.md` (이 파일) | 작업 규칙, 바뀌지 않는 전제 |
| 지도 | `README.md` | 폴더 구조, 실행 순서, 결과 요약 |
| 불변식 | `docs/invariants.md` | 항상 성립해야 하는 물리·수치 조건 |
| 결정 | `docs/adr/` | 왜 이렇게 정했는지와 버린 대안 |
| 기록 | `docs/run_log.md` | 실행할 때마다의 설정과 핵심 수치 |
| 분석 | `docs/YYYY-MM-DD_주제.md` | 그 시점의 해석과 한계 |

수치의 원본은 언제나 `outputs/`입니다. 문서는 거기서 읽어 온 것이고, 어긋나면 문서가 틀린 것입니다.

## 코드를 고치기 전에

솔버(`datraj/robot.py`, `task.py`, `planning.py`, `timing.py`, `astar.py`, `dose_eval.py`)를 고칠 때는 **"확실하냐"고 스스로 묻지 말고 사실을 먼저 확인하세요.** 다음을 말할 수 있어야 고칩니다.

1. 이 함수를 부르는 곳이 어디인가 (`grep`으로 확인)
2. 바뀌는 값의 단위와 좌표계는 무엇인가
3. `docs/invariants.md`의 어떤 조건에 영향을 주는가
4. 고친 뒤 어떤 스크립트를 돌려서 확인할 것인가

## 작업할 때

- 큰 작업은 `docs/`에 결과 문서를 남깁니다. 파일명은 `YYYY-MM-DD_주제.md`.
- 코드를 고쳤으면 관련 스크립트를 실제로 돌려서 끝까지 가는지 확인하고, 바뀐 수치를 문서에 반영합니다.
- 가정이나 방법을 새로 정했으면 `docs/adr/`에 한 장 남깁니다. "그냥 골랐다"는 근거가 아닙니다.
- 실행 결과는 `docs/run_log.md`에 한 줄 추가합니다.
- 한계와 가정을 숨기지 마세요. 분석 문서에는 "한계" 절이 반드시 들어갑니다.
- **검증이 끝까지 돌지 못했으면 "이상 없음"이라고 보고하지 마세요.** 확인하지 못한 범위를 분명히 밝힙니다. 확인 못 한 것은 통과가 아니라 미확인입니다.
